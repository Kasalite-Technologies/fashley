## Fabric selection burst (2026-10-31, branch `feat/fabric-selection-server`)

- Status: merged to main via PRs #9/#10 (`bb50ef0`/`06089e0`) and deployed (Worker `b13dded7`; IMAGES binding live; fabric-selection route verified 401-not-404 when unauthenticated).
- Server: `POST /api/tailor/projects/:id/fabric-selection` implements the frozen `fabricSelectionRequestSchema` / `fabricSelectionResponseSchema` contract. Success is 201; idempotent replay (operation `fabric_selection`) is 200 with the original `{selection, asset}`. The endpoint does not mutate drafts/revisions; the returned selection is persisted by the client into draft/revision input. Crop overflow (`x+width>1` or `y+height>1`) is rejected with `INVALID_INPUT` (no clamping). SAM selection is a bbox-rectangle crop of the source plus the region's `maskAssetId` (not a mask cutout). Cross-owner project/asset/job return `NOT_FOUND`; a region missing from a completed job, or a job/segmentation that is not completed, returns `INVALID_INPUT`. Sources over 12000px per side or 100MP are rejected with `INVALID_INPUT` before cropping.
- Images binding: `IMAGES: bindings.images()` added in `cloudflare.config.ts` and mirrored as `"images": {"binding":"IMAGES"}` in `wrangler.jsonc` (reference only; no `dev.remote`). The cropper adapter (`src/lib/tailor/server/cloudflare.ts`) converts the normalized rect to pixel `trim` values using the sanitized source dimensions, because the runtime types in `.cloudflare/types` define `trim` top/left/width/height as pixels, not fractions. Missing Images binding fails closed with `FEATURE_UNAVAILABLE`; transform failures fail closed with `PROVIDER_UNAVAILABLE`. Local trim behavior is unverifiable without a live Images binding — deploy smoke still pending.
- Evidence: new `fabric-selection.test.ts` (9 tests: manual crop happy path, overflow reject, SAM pick, cross-owner 404s, idempotent replay with cropper called once, unconfigured cropper, oversize reject, and pixel trim conversion/failure mapping) uses a fake cropper and fake Images binding; no real Images/network calls were made.

## Job recovery + history burst (2026-10-31, branch `feat/job-recovery-server`)

- Status: implemented on branch; pending merge, deploy, and live proof.
- `latestJob`: `getProjectDetail` no longer hardcodes `null`; it returns the newest `ai_jobs` row for the project (`created_at DESC, id DESC`), owner-scoped, serialized through the existing `toJob` mapper (`src/lib/tailor/server/projects.ts`). This makes in-flight/completed jobs — including the draft brief id in a completed `assemble_brief` result — reachable again after reload. Null when the project has no jobs.
- History: `GET /api/tailor/projects/:id/history` implemented to the existing client contract (`historyListSchema`, no contract/client changes): owner-scoped via `getOwnedProject` (cross-owner → `NOT_FOUND`), merging `project_revisions` (`revision`, "Input revision N saved"), `brief_revisions` (`brief`, "Brief N <state>"), `ai_jobs` (`job`, "Job <type> <state>"), and `review_actions` for the project's briefs (`review`, "Review <action> by <reviewer>"), sorted newest-first (`created_at DESC`, id tie-break) with `limit` clamped 1–50 (default 20) and an opaque `offset:<n>` cursor returned as `nextCursor`. All four kinds are sourced from real tables; nothing fabricated.
- Evidence: new `src/lib/tailor/server/history.test.ts` (7 tests: latestJob null/newest/owner-scoping incl. contract parse through `projectDetailSchema`, history four-kind shape + ordering + empty page + cursor pagination/invalid cursor parsed through `historyListSchema`, HTTP happy path + cross-owner 404).
