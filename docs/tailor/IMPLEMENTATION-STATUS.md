## Media + Meta jobs burst (2026-10-30, branch `feat/media-meta-jobs`)

- Live D1 check before the burst: 0 `app_users`, 0 `auth_identities`, 0 `tailor_projects`, 1 published template. The owner live sign-in/project proof is still outstanding.
- Upload pipeline (G2): `src/lib/tailor/server/media.ts` sniffs magic bytes against the declared MIME, parses dimensions (JPEG SOF, PNG IHDR, WebP VP8X/VP8/VP8L), rejects empty/oversize (>10 MiB)/corrupt/mismatched input with `UPLOAD_REJECTED`, and rebuilds the file dropping metadata (JPEG APP1/COM, PNG non-critical chunks with CRC32 verification, WebP EXIF/XMP). This is a metadata-stripping rebuild, not a pixel re-encode; no decode/re-encode exists in the Worker yet. `uploads.ts` implements consent-checked intents (receipt-idempotent), content receipt into quarantine, completion re-verifying and promoting to `private/{projectId}/{assetId}` in R2 `TAILOR_MEDIA`, and owner-only `GET /api/tailor/assets/:id` (private, no-store, nosniff). Person uploads remain gated off by `capabilities.personUpload`.
- Durable jobs (G3): `jobs.ts` creates idempotent `ai_jobs` rows with credit reserve/settle, dispatches through the `TAILOR_WORKFLOW` binding (`bindings.workflow` in `cloudflare.config.ts`, cross-Worker `script_name: fashley-tailor-workflow`), and `runJob` executes analyze_fabric / generate_concept / assemble_brief with `ai_step_runs` provenance. `POST /projects/:id/briefs` now returns `{job}` per contract once a Workflow binding exists. The companion Workflow Worker lives in `workers/tailor-workflow/` (exports `TailorWorkflow`, runs `runJob` in `step.do`) and is **not deployed**: without it, dispatch throws and job creation fails closed with `FEATURE_UNAVAILABLE`, exactly as before. Its bundling is unverified (no build/deploy run in this burst).
- Meta adapters: `meta.ts` calls the documented `POST https://api.meta.ai/v1/responses` with the Secrets Store `META_API_KEY` as Bearer: segmentation `sam-3.1`, understanding `muse-spark-1.3`, generation `muse-image-1.0`. Segmentation output must parse as JSON regions with base64 mask payloads, which are sanitized and stored as `fabric_mask` assets; unparseable provider output fails the job with `PROVIDER_UNAVAILABLE`. No fake regions, masks, or concepts are ever fabricated. No real Meta call has been made; credentials are unverified.
- Evidence: new tests media (13 with uploads), meta/jobs (12), HTTP integration (2: upload-to-asset-content with cross-user 404; jobs fail-closed then dispatch/replay). `bun run test`: 89/90 pass; the one failure is `src/components/DesignStudio.test.tsx` (legacy, no tailor imports), which passes in isolation (6/6) and flakes under full-suite parallel load. `bun run typecheck` pass; `bun run build` pass (route tree regenerated with the new upload/job/asset routes); `cloudflare.config.ts` evaluates under the cf config schema with the workflow binding. Tailor-only: `bunx vitest run src/lib/tailor` 63/63.
- Still open: deploy companion Workflow Worker then main Worker (owner approval), first real Meta call, fabric-selection endpoint (SAM region pick / manual crop), owner live sign-in + project proof in D1, G5 release evidence.
